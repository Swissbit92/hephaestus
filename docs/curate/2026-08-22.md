## The anchor score is measuring the wrong things here

> **Corrected 2026-08-22, after fixing it.** This section first claimed **18 of 58**
> penalty points were artifact. That was wrong, and wrong the same way most things were
> wrong this week: I did not run the check. Only **8** were. The corrected figures are
> below; the original estimate is left described rather than deleted, because a curate
> report that quietly edits its own numbers is worth less than one that shows them moving.

`42/100` should not be read as "this repo is half-rotten", but it is closer to fair than I
first credited:

- `dead_candidate_penalty` **6** — **entirely artifact**. All six candidates
  (`evals/harness/{report,runner,scoring,world}.py`, `sqlite_readonly/{db,nl}.py`) are
  referenced by 2–8 files each: a **100% false-positive rate**. Cause found on inspection —
  the detector's import regex captured only the module path after `from`, so
  `from harness import runner, scoring` never recorded `runner` or `scoring`. Fixed; the
  count is now 0.
- `gitignore_gap_penalty` **12** — **only 2 points were artifact**, not 12 as first
  claimed. `node_modules` is genuinely inapplicable (no `package.json` anywhere), but
  `dist`, `build`, `.coverage` and `htmlcov` are legitimately expected: this tree contains
  two real `pyproject.toml` files (`plugins/mcp-starter` and `plugins/sqlite-readonly`
  server projects) which can produce exactly those artifacts. I had called the whole
  category noise without checking which markers were present. The expectations are now
  gated on evidence per entry, and the penalty is 10.

That leaves `god_file_penalty` **40** as by far the dominant signal, and it merges two
different things: `render.py` at 2,136 lines is a genuine god file, while
`test_cms_render.py` (1,410) and `test_cms.py` (903) are test files, where length tracks
coverage rather than complexity.

Score after both fixes: **50**. This matters beyond one number — a generic metric that
reports a bad score for reasons the reader can falsify teaches people to ignore it, which
costs more than not having it. It matters in the other direction too: an audit that
dismisses a real penalty as noise is the same failure wearing the opposite sign.

## Backlog

Ranked by cost of leaving against cost of fixing.

### An agent can fix this unattended

1. **`cms/SKILL.md` has 5 tokens of headroom** (2,995 / 3,000). The next cms edit fails
   `skill_lint --strict`, and whoever hits it will be tempted to raise the threshold — the
   anti-pattern this skill names outright ("the skill moved, not the budget"). Precedent
   for the fix exists twice over: `references/design-rationale.md` and
   `references/shared-state.md`. *Leaving it costs a future contributor a confusing gate
   failure; fixing it is one section move.*
2. **8 of 10 documents have no `ai_summary`.** `triage` exists so a lookup reads one body
   instead of several, and it currently cannot route on 80% of the corpus — including
   `LESSONS_LEARNED.md`, which is exactly the document an agent should be routed to.
3. **`curate.md` documents `repo_metrics --json`, which does not exist.** A documented flag
   that exits 2 is drift of the cheapest possible kind to fix.
4. **`.crucible/evidence.json` matches no path glob**, so changing the repository's
   definition of proof requires no evidence. One path entry.

### This needs a human decision

5. **`repo_metrics.py`'s penalties assume a JS/build-tool repo.** Dead-module detection is
   100% false-positive here and the gitignore check flags absent tooling. This is a shipped
   generic plugin, so changing the scoring has blast radius across every consumer. Options:
   narrow the checks, weight them by detected project type, or document that the anchor
   score is only comparable against itself over time.
6. **`render.py` is 2,136 lines.** A genuine god file and the largest single source of the
   anchor penalty. Splitting it is a real refactor with real risk, against a module with
   1,410 lines of tests behind it.
7. **`skill-craft-merge`'s check is unmeasurable.** Decide between retiring it `unclear`
   with the instrument named, or building the session tracking its check assumed.
8. **`sync.py` fails silently on three realistic YAML inputs.** From the dependency spike
   ([sync-yaml-dependency-spike-2026](../research/sync-yaml-dependency-spike-2026.md)):
   reordered keys and flow style both yield **zero facts**, and a trailing comment is
   swallowed into the regex, producing a pattern that can never match. All three look
   exactly like "no drift found". The spike recommends ~20 lines of validation over a
   PyYAML dependency; the decision to take that recommendation is still open.
