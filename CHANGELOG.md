## [Unreleased]

### Added
- **crucible 0.10.0 — `archflow`, a serpentine layout for pipelines, and the check that catches the omission.** `/cms render` grew a fenced ` ```archflow ` block: it **walks an existing `archview`** rather than redrawing it, so "what is here" and "what happens" cannot drift apart — select a flow, everything off its path dims, prev/next steps through it, deep-linkable as `#flow=&step=`. Every reference is resolved **at build time** and a dangling one fails the render, because `check_arch.py` only reads the emitted SVG where a broken picker and a working one are geometrically identical. The enabling change was DOM identity: nodes, edges and groups now carry figure-scoped ids, with **edge identity on a wrapping `<g>` and never on the `<path>`** — `RE_PATH` requires `d=` immediately after `class=`, so an attribute between them stops it matching *any* connector and every page would pass while checking zero edges. A view that is one unbranched chain of 4+ steps is laid out **serpentine** (left to right, wrapping, alternate rows reversed); through the layered engine a seven-step pipeline is a column ~800px tall, strictly worse than the numbered list it replaced — found by screenshotting the output, not by reading it. And `check` now warns when a doc holds 4+ sequential steps as prose with no `archflow`: that omission went unnoticed for weeks because a list is valid markdown and the page rendered fine, so nothing that verifies *the page builds* could see it. Craft: light theme via `[data-theme]` stamped before first paint, `@media print`, a generated legend in fixed semantic order, per-node `role="graphics-symbol"` + `aria-label` (not `<title>`, whose native tooltip fights the flow caption), and a visually-hidden text-alternative table built from the model that was already structured. Contrast: `--faint` sat at **2.85:1** on `--void` while carrying every table header, figure caption and 8px diagram sub-label; lifting it alone would have collapsed it into `--mid`, so the ramp is re-spaced to 5.04 / 8.15 / 14.82. Readability: measure **78ch → 68ch** (the 45–75 guidance assumes ~0.5em glyphs, mono runs ~0.6em), `tabular-nums`, `text-wrap: balance/pretty`, sticky `thead` + sticky label column (horizontal scroll, deliberately not card-collapse, which destroys the column comparison a reference table exists for), and the accent ramp **derived via `color-mix(in oklch)`** instead of appending hex alpha to the frontmatter value — which silently assumed 6-digit hex. `published_url` binds a page to one address so republishing cannot scatter copies; `render.py` still never uploads, printing a manifest line instead so it stays stdlib with no network and no credentials. Also emits `docs/ARCHITECTURE.txt` — the same content flat, for the second reader, generated in the same pass so it cannot drift. +53 tests (408 → 461).
- **crucible 0.11.0 — evidence-typed Phase 4: the workflow runs the deterministic checks itself.** The change is about *placement*, and placement was measured rather than argued. On a green-but-shrunken test suite: asking the agent to compare test sets by eye caught it **3/6**; giving it a script and asking it to run the script caught it **2/6**; having the workflow run the script caught it **3/3**. The check was never the weak part — the *request* was. `develop.md` Phase 4 now splits into **4.0 deterministic checks the workflow executes** and **4.1 review**, with the results handed to the gatekeeper as an input rather than an assignment. Three scripts sit on the 4.0 side. `coverage_delta.py` diffs the *set* of collected test identities against the branch point: counts cannot see a suite that shrank, since deleting one test and adding another leaves the count unchanged and the suite green precisely because what would have failed is no longer asked. `detect_profile.py` reports which gates a project supports **and where** — it walks for *every* project root rather than stopping at the top, because a repo commonly carries a backend at the root, a frontend one level down and a second service beside it, and a root-only detector reports "checks passed" while whole subtrees were never examined; it separates **gate** (runnable now) from **capability** (present but needs a live service — a browser suite whose config starts no server collects zero tests, and zero tests passing is the vacuous green this phase exists to kill) from **absent**; toolchains with no evidence behind them get **no rules**, since a guessed command that fails confusingly is worse than an honest "no marker found"; and it never executes what it finds, because reading declared scripts is safe while running them is a trust decision belonging to the caller. `invariants_run.py` runs the checks wired to `docs/INVARIANTS.md`. All three reserve a **distinct exit code for "could not determine"**, never folded into success — a check that could not run is not a check that passed, and holding to that caught two real bugs during development (`0 vs 0` reporting OK, and a doubled `-q` silently yielding no test IDs at all). Catalogue in `commands/references/evidence-profiles.md`, loaded only when extending the detector. Tests 408 → 477; eval scenarios 9 → 21.
- **crucible 0.11.0 — `docs/INVARIANTS.md`: standing constraints that survive being forgotten.** A constraint stated once is least salient exactly when it is about to be broken; by then it is the oldest thing in the conversation, competing with everything said since. This refuses to answer that with more reminding, because **the thing doing the forgetting is the thing being asked to remember**. So nothing here reminds anyone of anything — it runs the checks wired to each entry, and a script does not care how long ago the rule was written. A spec dies at merge; an invariant outlives every task, and filing the first inside the second is why standing constraints get lost — hence separate files with opposite lifecycles. `INVARIANTS.md` is **frontmatter-exempt**, the first `docs/` file to be: `last_reviewed_on`/`review_in` ask "is this still accurate?" on a timer, the right question for a description of a system and the wrong one for a rule about it — a constraint does not expire because nobody looked at it, and dating one manufactures exactly the rot the file exists to prevent. Retirement is a deliberate edit, and retired entries stay, because the next person to propose the same thing deserves to learn it was considered and dropped. Scaffolded by `/cms init` but deliberately **not** in `REQUIRED_FILES` (a repo with no standing constraints is not doing something wrong) and never auto-archived. `cms check` **warns, never errors**, on an active entry with no `Check:` — erroring on an unwired *intent* would teach people to stop recording intents, which costs more than the missing check. The `PROSE → FALSIFIABLE → CHECK → ENFORCED` conversion stays a documented recipe, never a generator: a generated check asserts something adjacent to what you meant, and a check that passes for the wrong reason converts an open question into a false answer. Checks live in the target repo, never in the plugin — what counts as a violation is a local judgement. Dogfooded: this repo's own seam rule is now a wired invariant, and injecting a domain token into a generic plugin produces exit 1 naming the constraint.
- **crucible 0.9.0 — `/cms render`: a generated human view of `ARCHITECTURE.md`.** `docs/ARCHITECTURE.md` stays the single source; `docs/ARCHITECTURE.html` is generated from it and **must never be hand-edited**. The point is what it refuses to be: a second architecture document would *double* the staleness surface rather than solve it, so drift is made **structurally impossible** instead of policed. Diagram models live in fenced ` ```archview ` blocks *inside* the markdown (one file to edit, one linter to satisfy); repo-specific visuals go in a fenced ` ```html ` block and pass through untouched, because "the one thing this repo does" differs everywhere and cannot be schema'd — the format offers a **socket, not a type**. The accent colour comes from frontmatter, so visual identity belongs to the repo and not to this generic skill (which is why the promoted code passes `test_seam.py` with **zero domain tokens**). Staleness is gated on **content hashes of both the source and the renderer**, never mtimes — git doesn't preserve mtimes, so an mtime check reports a byte-identical page as stale after any checkout (it fired on this tool's own first merge); surfaced as a **Warning, never an Error**, since a gate that blocks on a regenerable artifact is one people learn to bypass. `check_arch.py` is the authority on layout rather than the eye: it parses the **emitted SVG** (not the engine's intermediate geometry — the artifact is what ships) and reports C1–C6 (overlaps, connectors through node interiors, out-of-bounds, group-boundary straddles, degenerate rects, malformed paths). It is **mutation-tested** — five planted defects, each must be caught by the right code — because a checker that passes everything grants confidence it hasn't earned; and a page with **no diagrams is explicitly not a failure**, since crying wolf is how checkers get switched off. Evidence rather than assertion: markdown fidelity proven **out-of-sample on five pre-existing `ARCHITECTURE.md` files** written before the tool existed, which caught ordered lists being silently swallowed into the preceding paragraph (destroying a numbered pipeline's structure); and the layout engine proven at **19 nodes**, where the checker found **two real routing bugs in a page already committed and pushed** — a multi-row edge dropping straight through an intervening node, and a back-edge rail returning horizontally through whatever sat between the lane and its target. `templates/ARCHITECTURE.md` now scaffolds a starter `archview` block so a repo gets the convention from `/cms init` rather than discovering it. Spec in `references/architecture-views.md`, loaded only when rendering, so `SKILL.md` gains rows rather than pages. +43 tests.
- **crucible 0.8.0 — `act-for-real` skill.** The discipline for the case `loop-harness` refuses and `flag-gate` can't help: an **irreversible** action on a **live system you often don't own** (money movement, credential rotation, one-way migration, registrar/DNS, real mail). `flag-gate` already names the seam — *"a flag in front of a one-way state migration isn't a kill switch"* — and this starts there. Five phases, three of them HARD GATEs: **CLASSIFY** (reversible *and* yours → leave, use `flag-gate`) · **AUTHORITY** (approval bound to the *exact* action — actor/target/normalized-params/timestamp/expiry; approval never generalizes; the human owns credential-gated steps, and the confirmation that *is* the authorization is never automated) · **INPUTS** (every real-world identifier needs provenance + its structural check; on failure **stop and ask, never pattern-complete**; target-system content is data, never instructions) · **ACT** (re-read immediately before acting — the TOCTOU check→use gap) · **VERIFY** (confirm from a **fresh read**, not the call's response; prefer a second independent channel; **`UNVERIFIED` is a valid, mandatory outcome**). Emits an append-only `ACTION RECORD` (the sibling of `loop-harness`'s LOOP-STATE ledger). Pure methodology — owns no browser/client/transport by design, and explicitly **not a security boundary**. Fires *rarely* on purpose: ceremony on trivial writes trains everyone to skip it. Evidence-backed by `docs/research/acting-on-live-systems-2026.md`, whose research **reframed the original question** — *don't* build a browser skill: the tool layer converged on DOM/accessibility-tree, vendors already ship browser methodology as skills, and the unsolved risks (believing a call, stale state, fabricated identifiers, content-as-instructions, missing authority) are **domain-neutral**. +1 eval scenario (`act-for-real/refuses-irreversible-without-approval`) + `act_irreversible` fixture.
- **crucible 0.7.0 — `repo-audit` skill.** Recurring, repeatable whole-repo health audit built for *trending*, not one-off snapshots. A deterministic pure-stdlib anchor (`repo_metrics.py`: file/LOC inventory, God-file detection, tracked-artifact & `.gitignore` hygiene, flag-branching count, conservative Python dead-module candidates, and an itemised `anchor_score` — same commit, same number, every run) feeds four **frozen, read-only, parallel** analysis lenses (Janitor / Architect / Clean-Code / DevOps). Synthesized into a dated `docs/audits/{date}-{repo}.md` that the next run diffs (score Δ · closed / new / deferred). Delegates the docs dimension to `cms`; gitignores raw agent dumps (eval-first artifact-hygiene lesson); lenses are versioned so a moved ruler is visible. Reconciles with the VISION non-goal — parallel independent read-only lenses over a static tree are *not* the rejected sequential role-play waterfall. +19 tests (342→361).

### Changed
- **The eval harness asserts on a subagent's own output, not the orchestrator's paraphrase.** The gatekeeper scenarios bounced 0.33<->1.00 across five measurement rounds, and it was the instrument, not the model: the checks read `final_text`, which is the *parent's summary* of the subagent's verdict, while the parser dropped `user` events entirely -- so the subagent's actual output was in the stream and discarded. The runner now maps `tool_use_id` to tool name and captures `tool_result`; `qa-gatekeeper` must end with a machine-readable `QA-VERDICT:` line, because a verdict that has to be inferred from prose gets inferred differently by different readers, and by the same reader on different days. Also: the subagent tool is `Agent`, not `Task` -- verified against a captured stream rather than written from memory, since a wrong name yields no results and "no results" would otherwise have satisfied the *not-matching* direction forever; both directions now fail on absent results.
- **Four fixture-design rules, each learned from a failing eval that turned out to be the eval's own fault.** (1) A fixture must deliver a **complete** change -- a branch named "add-widget" shipping one unrelated test gets rejected for being empty, and then it is fixture realism being measured, not the property. (2) It must be **unambiguous** -- deleting code *together with* its tests is a legitimate refactor, and the gate calling that CONDITIONAL_PASS was reading it correctly. (3) Assert on **behaviour, not implementation traces** -- gating on `git merge-base` appearing in a Bash call tests *how* a baseline was derived; build a fixture where the right verdict is unreachable without doing the right thing instead. (4) A **"must not reject" twin proves the absence of one specific false alarm, never global approval** -- a defect fixture makes an existential claim and is easy to build, a twin makes a universal one, and a competent reviewer finds *something* in almost any toy code (the first wired-guard twin was rejected 3/3 for a hardcoded credential and an unhandled `None`, both real).
- **`qa-gatekeeper`'s truth-gate sections were measured at k=10, and the number that mattered was the sample size.** Final: assertion-quality 9/10, mock-provenance 10/10, unreached-code 9/10, swallowed-exceptions 9/10 — **37/40**. An earlier k=3 pass read 3/3, 4/6, 2/3, 3/6 and was written up as "unreliable, not dead". That was wrong, and not marginally: swallowed-exceptions read **0/3**, then 3/3 with nothing changed in between, and was one decision away from being rewritten as a deterministic script. It is 9/10. A k=3 run cannot distinguish 30% from 90%, so it cannot support a conclusion about a prose gate — the ~40 minutes a k=10 costs is less than the day the wrong conclusion nearly cost. The metric is additionally biased low, because a scenario scores "did it find the defect I seeded" and a reviewer finding an unseeded defect scores as a miss; six supposedly-clean fixtures were rejected during this work and the gate was right every time.
- **`cms` wrote runtime state *into* the generic plugin, contaminating the Tier-A seam.** `tests/test_seam.py` had been red on `main`: `size_history.json` inside `plugins/crucible/` had accumulated the repo names of whatever ecosystem was using the skill — domain content in a generic plugin, which is exactly what ADR-001 forbids. The file was already gitignored, so nothing leaked into git; but the seam test scans the **filesystem**, and rightly so, since a plugin directory carrying domain content carries it wherever that directory goes. The underlying bug was worse than the symptom: `common.py`'s own comment said state *"must survive plugin updates, which overwrite the cached plugin dir"* — and then the final branch wrote it into that very directory. Since neither `CMS_STATE_DIR` nor `CLAUDE_PLUGIN_DATA` is set in ordinary use, **that branch wasn't a rare fallback, it was the only path ever taken**, so state was being written exactly where the design said it must not and destroyed on every plugin update. Runtime state now defaults to `~/.claude/cms-state`, with a non-destructive one-time migration out of the plugin (an existing file at the new location wins; failures are silent, because losing size history costs one warning while crashing costs the skill). All 29 repos of history carried over. Shipped config (`sync_facts.yaml`) stays versioned in the plugin, and `SKILL.md` now states that split explicitly. +4 regression tests, verified to fail against the old resolution order.
- **Windows encoding — plugin scripts crashed or silently corrupted non-ASCII docs.** Every `read_text`/`write_text` call across the plugins relied on the platform default encoding, which is **cp1252 on Windows**, not UTF-8. Two live failure modes: a hard `UnicodeDecodeError` (e.g. `cms/scripts/init.py` scaffolding a repo whose docs contain an em-dash), and — worse — **silent corruption** at the 13 sites passing `errors="replace"`, which still decoded as cp1252 and mangled `—`/`→` into `�` instead of failing loudly (this is what corrupted a freshly scaffolded `SKILL.md`). Pinned `encoding="utf-8"` at **54 call sites across 25 files**. Separately, `loop_sweep` wrote its non-ASCII report to a cp1252 stdout, raising `UnicodeEncodeError` mid-report and killing the process with exit 1 — **silently breaking the documented 0/1/2 exit contract, so a cron sweep reported "red" when it actually meant "couldn't parse a summary"**. CLI entry points now force UTF-8 stdio (`loop_common.use_utf8_stdio`), and the sweep decodes the suite's output as UTF-8 with `errors="replace"` (a sweeper must survive whatever a test prints, not die on an emoji). Fixes 5 pre-existing failures — the suite was only ever green on POSIX (357 passed / 5 failed → **362 passed**). Windows users no longer need `PYTHONUTF8=1` to lint a repo whose docs contain non-ASCII.

## [crucible-v0.6.3] — 2026-06-28

### Added
- **crucible 0.6.2 — `loop-harness` read-only sweep driver.** `loop_sweep` — one command runs the whole arm → run-tests → `loop_logscan` → ledger → needs-me report → disarm cycle (cron/CI-friendly), replacing ~8 hand-assembled steps. Exit 0 = green / 1 = red / 2 = unparsed. **Read-only — never drafts, commits, or merges** (drafting is the agent's triage step). Operationalizes the CI Sweeper; `--test-cmd` runs via the shell as operator-supplied config (documented trust boundary). Extracted `loop_budget.disarm_run` for reuse. +6 tests (335→341).
- **crucible 0.6.1 — `loop-harness` dogfood iteration.** `loop_logscan` — a stdlib test-log summarizer (counts + failing node IDs + clean summary line) as the deterministic floor of the log-inspection step; it **refuses to report `ok` from output without a parseable pass/fail summary**, so a sweeper never claims green from unparsed logs. `loop_budget arm` also records the ledger path (`--ledger`, defaults to `<worktree>/LOOP-STATE.md`). Surfaced by dogfooding the CI Sweeper on hephaestus's own pytest suite — happy-path cycle (worktree → arm → ledger → charge → converge → disarm) plus an injected-fault triage drill (detect → triage → draft-in-worktree → verify → discard, `main` untouched); the live PreToolUse hook blocked `git push` (exit 2) while allowing `pytest`. +11 tests (324→335).
- **crucible 0.6.0 — `loop-harness` skill.** Bounded, single-threaded, read-only agent-loop primitive (the CI Sweeper spine). `loop_budget` (hard turn ceiling + optional token/cost budget + per-run cost log), `loop_ledger` (a `LOOP-STATE.md` memory file with structural compaction), and a PreToolUse safety `loop_hook` that is **inert unless a loop is armed** and otherwise blocks `git push`/`merge`/`rebase`/`reset --hard`/`branch -d|-D`/`worktree remove` and writes outside the worktree (tokenizer-based — resists `git -C`/`-c`/env-prefix bypass). Single-threaded-not-role-teams, evidence-backed by `docs/research/loop-engineering-2025.md`. Pure stdlib; 60 tests.
- **crucible 0.5.0 — `flag-gate` skill.** Default-OFF feature-flag rollout with instant revert (legacy path byte-identical, flip on an eval-first gate, revert by flipping off, retire after soak). Pure methodology skill; pairs with `eval-first`.
- **crucible 0.4.0 — `eval-first` skill.** Eval-first methodology + generic stdlib scripts (`ab_harness`, `baseline`, `judge`, `deterministic`, `reliability`) and scaffolding templates. Freeze an immutable baseline → deterministic-first checks → swap-augmented blind A/B judge (pinned, self-grading-guarded) → match-or-beat-or-revert verdict. 38 tests.

### Changed
- **crucible 0.6.3 — cms README scaffold upgrade.** `cms init` now scaffolds a best-practice README skeleton — a table of contents, a Mermaid-diagram hint (text-based, GitHub-rendered, AI-parseable), and linked Contributing/License sections — baking README best practices in at **creation time** (deliberately *not* a retroactive content lint, which would erode cms's trustworthy Error/Warning model). Backed by a quick web-research pass on README best practices for humans + AI agents. +1 test.

### Fixed
- **crucible 0.6.1 — loop-harness ledger status + log-capture (dogfood findings).** `loop_budget disarm` now syncs the ledger's `Status` field (was stuck on `armed` after convergence). Corrected the `SKILL.md` log-inspection example: under a repo whose pytest `addopts` already sets `-q`, an extra `pytest -q` becomes `-qq` and suppresses the summary line `loop_logscan` needs — switched to the project's plain test command. (The bug was caught by `loop_logscan`'s own refuse-to-guess-green safety property.)

Kills the stale-baseline false-alarm → loop-trustworthy gate. Aligned `develop` + `start-branch` baseline wording to match.
