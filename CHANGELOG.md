## [Unreleased]

### Added
- **A skill-quality gate, and a duplication metric that counts passages instead of windows.** `validate_manifests.py` proves a plugin is well-formed and `test_seam.py` proves it is domain-free; neither can see the two ways a skill *library* decays — a `SKILL.md` quietly outgrowing the context budget it is charged against on every session that loads it, and two skills drifting into saying the same thing, which no single diff introduces and so review cannot catch. `scripts/skill_lint.py` checks frontmatter conformance and naming (ERROR), token budget, unsanctioned keys and cross-skill overlap (WARN); `--strict` makes warnings fail and is what CI runs. The metric is deliberately **not** a shared-shingle count, and the reason is the first thing it found: sliding 12-word windows over *one* shared sentence yields nine or ten "shared shingles", so `act-for-real`↔`flag-gate` (both stating that a flag in front of a one-way migration is not a kill switch) and `grill-me`↔`spar-with-me` (both drawing the deciding-versus-being-talked-out-of-it distinction) were reported as nine and six defects. Both are the **"pairs with" convention working as intended** — deliberate cross-references, each skill telling the reader which sibling to reach for. So overlapping windows are merged back into maximal runs and the check reports distinct passages, warning on two or more runs or a single run past 30 words (a pasted paragraph, not a cross-reference). The prose was right; the measurement was wrong, and lowering a threshold instead would have hidden that. The one real finding is fixed: `cms` was ~3257 tokens, and its `Rendered architecture view` section was a 14-bullet summary of the 19 KB `references/architecture-views.md` sitting beside it — it now keeps the four rules an agent could violate without opening the reference and sends the schema catalogue there. CI also gains a **`cross-platform` job** (macOS + Windows), added as a *separate job* rather than a matrix on `checks`, because branch protection requires a status check named exactly `checks` and matrixing renames it to `checks (ubuntu-latest)`, detaching the rule with nothing appearing to break. +20 tests.
- **crucible 0.14.0 — `refactor-audit` and `session-to-skill`.** Two gaps named by what the library already had. `repo-audit` says outright that it is not for reviewing a single change and code review looks for defects, so nothing audited **one body of work** — a range, a branch, the working diff — for what it would take to reach production quality; `refactor-audit`'s centre of gravity is the *ranking* (a flat list of thirty observations gets skimmed and the two that mattered go with it) and the split between what an agent can fix unattended and what needs a human decision, since those are read by different people. Its two rails: every finding names the standard it fails, and **the project's own conventions outrank generic best practice** — an audit that re-litigates a settled decision gets discarded wholesale, taking its correct findings with it. `session-to-skill` runs the other direction from `author-skill`: that one starts from an intention someone already has, this one starts from a transcript and must first decide whether there is a skill in it at all, generalising the process rather than snapshotting the task, with refusal as the honest default — a library of thin near-duplicate skills taxes every future routing decision. Both pass `skill_lint --strict` against the existing thirteen, which is why the linter was built first.
- **`cms triage` — retrieval on summaries, not bodies.** The `@path`-versus-plain-link rule governs what loads unconditionally; nothing governed what loads *while you are still looking*, which is the half that grows with the corpus. Searching by opening candidates costs the full text of everything you opened and were wrong about — free at ten documents, most of a context window at fifty. Documents may now declare an optional `ai_summary` and `triage.py` prints a routing table (path, status, summary; never bodies). Three properties keep it from becoming the cost it removes: a summary says what a document **is and when to open it**, never what is in it (the second kind is a second copy that goes stale on its own schedule, which is worse than none because it is trusted); it is **bounded** at 1500 bytes and re-read on every pass, so `check` warns past the cap — a Warning, since the document is still valid, it has just stopped earning its place in the index; and it is **optional, with unsummarised documents listed anyway**, marked and sorted last, because an index that silently omitted them would route confidently around the part of the corpus it cannot see. Optional is deliberate: requiring it would invalidate every document already on this schema, and a summary written to satisfy a linter is worse than none. Adding it pushed `cms` back over the 3000-token budget the same release introduced — the gate working, not obstructing — so `Skill principles` (306 tokens of provenance, read when deciding whether a rule should change, which is rare) moved to `references/design-rationale.md` and the shared-state mechanics to `references/shared-state.md`. +6 tests.
- **second-brain 0.3.0 — the vault health report is computed, not read for.** `review` asked four questions that are pure counting — what links to nothing, what nothing links to, which links resolve to no note, which tags are variants of each other — and answered them by having the model read the whole vault: cost proportional to vault size, untestable, and a slightly different answer each run, so a vault could never be trended. A health report you cannot compare with last month's is a mood. `scripts/vault_graph.py` does the counting in one pass (exit 0 = report, 2 = could not determine — an empty vault is not a clean bill of health), parsing what Obsidian actually does rather than what wikilinks look like: aliases, headings, block refs and embeds all resolve to the same target, links inside fenced or inline code are examples rather than links (without which any note documenting `[[wikilink]]` syntax manufactures broken links), and a link resolves by note *name*, not only by path. Two deliberate refusals: it pairs tags differing by case, separator, plural or typo and will **never** pair `#ml` with `#machine-learning` — they share no substring and no string metric finds them, so the report names the limit and leaves that judgement to the model, where propose-then-confirm requires it to sit; and `_meta/tags.md` is excluded from the note set, since counted as a note it is a permanent orphan and its declarations turn every approved tag into a phantom "used once", burying the real singletons. +18 tests.
- **crucible 0.13.0 — `cms site`: a multi-repo documentation site built from the markdown that already exists.** `site.py <root>` assembles the docs living next to the code into one navigable site, driven by a `site.toml` that lists repositories **and nothing else**. It authors nothing — every page is an existing file rendered through the same engine the standalone pages use, so diagrams, tours and plots work unchanged. The rule that makes it generic across repos without per-repo configuration is **a page exists if its sources exist**: a repo with no `DEPLOYMENT.md` has no "Running it" entry and no dead link pointing at one, and dropping the file in later is the whole of the work. There is no manifest to update and therefore **no way for the nav to promise a page nobody wrote**. Documents that no named section claims still get pages of their own — without that the site is a curated subset that *looks* complete while quietly dropping most of a repo. The renderer was generalized to match: it renders **any** document rather than only `ARCHITECTURE.md`, and titles now come from the document itself (frontmatter `title`, then a map of cross-industry conventional filenames — README, CHANGELOG, SECURITY — then a readable form of the filename), so no caller has to declare what a document is. That generalization exposed a real bug: `md_path.parents[1].name` assumed every document lives under `docs/`, so a root-level `SECURITY.md` reported the **parent directory of the repo** as its repo; the repo root is now threaded through explicitly. Search indexes every page including the unclaimed reference documents, and holds the whole index **inline on one page** rather than fetching it — a fetch is simpler but would make that page the only one on the site requiring a server to behave a particular way, and every other page opens from a `file://` URL. Highlighting **walks the string instead of compiling a `RegExp` from the query**, because building a pattern out of whatever a reader typed means escaping every metacharacter correctly, and getting that subtly wrong is how a search box starts throwing on a bracket (verified with a `[bracket` query, which now returns "nothing matched"). Topology diagrams gained cross-repo links: a node whose **exact** label matches a configured repo name offers "open &lt;repo&gt;" in the readout — deliberately strict, since anything looser starts inventing links, and a document can set `href` by hand for what the matcher will never guess. It is a readout entry rather than a click target, because clicking a node already means "inspect this" and silently changing that to "navigate away" is a trap. Finally, the bug worth the most: `docs/README.md` and `docs/lore/README.md` both slugified to `ref-readme`, so the second **silently overwrote** the first — nothing failed, nothing warned, and the only trace was a page count of 167 against 166 files on disk. That is the worst shape a bug can take in a documentation site: it looks complete and one document is simply gone. Slugs now carry their path under `docs/`, and a duplicate **raises instead of writing**. `tests/test_cms_render.py` at 143 collected.
- **crucible 0.12.0 — `spar-with-me`, and the discovery that `grill-me`'s problem was routing, not tone.** The complaint was that `grill-me` felt too aggressive to reach for. It was not miscalibrated on intensity — it was miscalibrated on **lifecycle stage**: every phase in it attacks a position, which only works if the user *has* one, and its description ended with *"or needs a thinking partner on a non-trivial choice"* — a clause that pulled it into exactly the half-formed-idea moments it is worst at, then grilled the user for not having a thesis. So the fix is one line of description plus a sibling, not a rewrite: **`spar-with-me`** takes the forming stage, `grill-me` keeps the commit stage and its falsifiable-tripwire close (which nothing else in the plugin does), and each names the handoff to the other — which also gives `grill-me` its first inbound edge. Three properties carry the new skill. **Research is unconditional and two-sided** — internal *and* web, every time, never a judgement call: web-only confidently proposes what a repo already rejected for reasons that still hold, internal-only re-derives what the field settled years ago, and where the two disagree is usually the most valuable thing in the session. **Read-only is structural, not worded** — fan-out goes to `Explore`/`Plan` agents that carry no write tools *by construction*, because "change nothing" is stated at turn 1 of a conversation that is by nature long and multi-turn, and the same placement-beats-wording result that moved the Phase 4.0 checks applies to any constraint that must survive twenty turns. And the anti-sycophancy rule is given a **falsifiable form** — *change position on new evidence or a new argument, never on restated preference or displeasure, and say which just happened* — because "be honest" is the same class of instruction as the pushback it must withstand and loses to it on recency; models flip correct→incorrect on user rebuttal roughly 1 in 7 times. The rule is deliberately indifferent to the *direction* of an update and picky only about its *cause*, since a rule that made positions sticky would just be wrong more stubbornly. Reconciled against the VISION non-goal exactly as `repo-audit` is: one conversational agent with independent, read-only, parallel research fan-out is not the rejected role-play waterfall. Evidence in `skills/spar-with-me/references/honest-take.md`. +3 eval scenarios (21 → 24) and a `spar_idea` fixture whose repo-local ADR contradicts the textbook web answer — so the internal-research check cannot be satisfied by plausible-sounding prose.
- **A test for the eval README's scenario table.** It had drifted silently — rows were added to the suite and never to the table — and nothing caught it, including a prior claim that it was already checked. `test_readme_table_lists_every_scenario` asserts **set equality in both directions**, since a stale table understates *or* overstates coverage and a reader cannot tell which. Verified to fire on a removed row rather than passing vacuously. Alongside it, `test_every_scenario_is_wired_correctly` now asserts the **named artifact exists**: a scenario pointing at a renamed or deleted skill still runs, it just invokes nothing — and a run that invokes nothing satisfies every "must not do X" check perfectly, a silent false pass in the reassuring direction. Renaming this very skill mid-review is what surfaced the gap. Scoped to skip plugin-level scenarios (`skill == plugin`, e.g. the `sqlite-readonly` MCP server), where the existing plugin-directory assert is already the right check.
- **crucible 0.10.0 — `archflow`, a serpentine layout for pipelines, and the check that catches the omission.** `/cms render` grew a fenced ` ```archflow ` block: it **walks an existing `archview`** rather than redrawing it, so "what is here" and "what happens" cannot drift apart — select a flow, everything off its path dims, prev/next steps through it, deep-linkable as `#flow=&step=`. Every reference is resolved **at build time** and a dangling one fails the render, because `check_arch.py` only reads the emitted SVG where a broken picker and a working one are geometrically identical. The enabling change was DOM identity: nodes, edges and groups now carry figure-scoped ids, with **edge identity on a wrapping `<g>` and never on the `<path>`** — `RE_PATH` requires `d=` immediately after `class=`, so an attribute between them stops it matching *any* connector and every page would pass while checking zero edges. A view that is one unbranched chain of 4+ steps is laid out **serpentine** (left to right, wrapping, alternate rows reversed); through the layered engine a seven-step pipeline is a column ~800px tall, strictly worse than the numbered list it replaced — found by screenshotting the output, not by reading it. And `check` now warns when a doc holds 4+ sequential steps as prose with no `archflow`: that omission went unnoticed for weeks because a list is valid markdown and the page rendered fine, so nothing that verifies *the page builds* could see it. Craft: light theme via `[data-theme]` stamped before first paint, `@media print`, a generated legend in fixed semantic order, per-node `role="graphics-symbol"` + `aria-label` (not `<title>`, whose native tooltip fights the flow caption), and a visually-hidden text-alternative table built from the model that was already structured. Contrast: `--faint` sat at **2.85:1** on `--void` while carrying every table header, figure caption and 8px diagram sub-label; lifting it alone would have collapsed it into `--mid`, so the ramp is re-spaced to 5.04 / 8.15 / 14.82. Readability: measure **78ch → 68ch** (the 45–75 guidance assumes ~0.5em glyphs, mono runs ~0.6em), `tabular-nums`, `text-wrap: balance/pretty`, sticky `thead` + sticky label column (horizontal scroll, deliberately not card-collapse, which destroys the column comparison a reference table exists for), and the accent ramp **derived via `color-mix(in oklch)`** instead of appending hex alpha to the frontmatter value — which silently assumed 6-digit hex. `published_url` binds a page to one address so republishing cannot scatter copies; `render.py` still never uploads, printing a manifest line instead so it stays stdlib with no network and no credentials. Also emits `docs/ARCHITECTURE.txt` — the same content flat, for the second reader, generated in the same pass so it cannot drift. +53 tests (408 → 461).
- **crucible 0.11.0 — evidence-typed Phase 4: the workflow runs the deterministic checks itself.** The change is about *placement*, and placement was measured rather than argued. On a green-but-shrunken test suite: asking the agent to compare test sets by eye caught it **3/6**; giving it a script and asking it to run the script caught it **2/6**; having the workflow run the script caught it **3/3**. The check was never the weak part — the *request* was. `develop.md` Phase 4 now splits into **4.0 deterministic checks the workflow executes** and **4.1 review**, with the results handed to the gatekeeper as an input rather than an assignment. Three scripts sit on the 4.0 side. `coverage_delta.py` diffs the *set* of collected test identities against the branch point: counts cannot see a suite that shrank, since deleting one test and adding another leaves the count unchanged and the suite green precisely because what would have failed is no longer asked. `detect_profile.py` reports which gates a project supports **and where** — it walks for *every* project root rather than stopping at the top, because a repo commonly carries a backend at the root, a frontend one level down and a second service beside it, and a root-only detector reports "checks passed" while whole subtrees were never examined; it separates **gate** (runnable now) from **capability** (present but needs a live service — a browser suite whose config starts no server collects zero tests, and zero tests passing is the vacuous green this phase exists to kill) from **absent**; toolchains with no evidence behind them get **no rules**, since a guessed command that fails confusingly is worse than an honest "no marker found"; and it never executes what it finds, because reading declared scripts is safe while running them is a trust decision belonging to the caller. `invariants_run.py` runs the checks wired to `docs/INVARIANTS.md`. All three reserve a **distinct exit code for "could not determine"**, never folded into success — a check that could not run is not a check that passed, and holding to that caught two real bugs during development (`0 vs 0` reporting OK, and a doubled `-q` silently yielding no test IDs at all). Catalogue in `commands/references/evidence-profiles.md`, loaded only when extending the detector. Tests 408 → 477; eval scenarios 9 → 21.
- **crucible 0.11.0 — `docs/INVARIANTS.md`: standing constraints that survive being forgotten.** A constraint stated once is least salient exactly when it is about to be broken; by then it is the oldest thing in the conversation, competing with everything said since. This refuses to answer that with more reminding, because **the thing doing the forgetting is the thing being asked to remember**. So nothing here reminds anyone of anything — it runs the checks wired to each entry, and a script does not care how long ago the rule was written. A spec dies at merge; an invariant outlives every task, and filing the first inside the second is why standing constraints get lost — hence separate files with opposite lifecycles. `INVARIANTS.md` is **frontmatter-exempt**, the first `docs/` file to be: `last_reviewed_on`/`review_in` ask "is this still accurate?" on a timer, the right question for a description of a system and the wrong one for a rule about it — a constraint does not expire because nobody looked at it, and dating one manufactures exactly the rot the file exists to prevent. Retirement is a deliberate edit, and retired entries stay, because the next person to propose the same thing deserves to learn it was considered and dropped. Scaffolded by `/cms init` but deliberately **not** in `REQUIRED_FILES` (a repo with no standing constraints is not doing something wrong) and never auto-archived. `cms check` **warns, never errors**, on an active entry with no `Check:` — erroring on an unwired *intent* would teach people to stop recording intents, which costs more than the missing check. The `PROSE → FALSIFIABLE → CHECK → ENFORCED` conversion stays a documented recipe, never a generator: a generated check asserts something adjacent to what you meant, and a check that passes for the wrong reason converts an open question into a false answer. Checks live in the target repo, never in the plugin — what counts as a violation is a local judgement. Dogfooded: this repo's own seam rule is now a wired invariant, and injecting a domain token into a generic plugin produces exit 1 naming the constraint.
- **crucible 0.9.0 — `/cms render`: a generated human view of `ARCHITECTURE.md`.** `docs/ARCHITECTURE.md` stays the single source; `docs/ARCHITECTURE.html` is generated from it and **must never be hand-edited**. The point is what it refuses to be: a second architecture document would *double* the staleness surface rather than solve it, so drift is made **structurally impossible** instead of policed. Diagram models live in fenced ` ```archview ` blocks *inside* the markdown (one file to edit, one linter to satisfy); repo-specific visuals go in a fenced ` ```html ` block and pass through untouched, because "the one thing this repo does" differs everywhere and cannot be schema'd — the format offers a **socket, not a type**. The accent colour comes from frontmatter, so visual identity belongs to the repo and not to this generic skill (which is why the promoted code passes `test_seam.py` with **zero domain tokens**). Staleness is gated on **content hashes of both the source and the renderer**, never mtimes — git doesn't preserve mtimes, so an mtime check reports a byte-identical page as stale after any checkout (it fired on this tool's own first merge); surfaced as a **Warning, never an Error**, since a gate that blocks on a regenerable artifact is one people learn to bypass. `check_arch.py` is the authority on layout rather than the eye: it parses the **emitted SVG** (not the engine's intermediate geometry — the artifact is what ships) and reports C1–C6 (overlaps, connectors through node interiors, out-of-bounds, group-boundary straddles, degenerate rects, malformed paths). It is **mutation-tested** — five planted defects, each must be caught by the right code — because a checker that passes everything grants confidence it hasn't earned; and a page with **no diagrams is explicitly not a failure**, since crying wolf is how checkers get switched off. Evidence rather than assertion: markdown fidelity proven **out-of-sample on five pre-existing `ARCHITECTURE.md` files** written before the tool existed, which caught ordered lists being silently swallowed into the preceding paragraph (destroying a numbered pipeline's structure); and the layout engine proven at **19 nodes**, where the checker found **two real routing bugs in a page already committed and pushed** — a multi-row edge dropping straight through an intervening node, and a back-edge rail returning horizontally through whatever sat between the lane and its target. `templates/ARCHITECTURE.md` now scaffolds a starter `archview` block so a repo gets the convention from `/cms init` rather than discovering it. Spec in `references/architecture-views.md`, loaded only when rendering, so `SKILL.md` gains rows rather than pages. +43 tests.
- **crucible 0.8.0 — `act-for-real` skill.** The discipline for the case `loop-harness` refuses and `flag-gate` can't help: an **irreversible** action on a **live system you often don't own** (money movement, credential rotation, one-way migration, registrar/DNS, real mail). `flag-gate` already names the seam — *"a flag in front of a one-way state migration isn't a kill switch"* — and this starts there. Five phases, three of them HARD GATEs: **CLASSIFY** (reversible *and* yours → leave, use `flag-gate`) · **AUTHORITY** (approval bound to the *exact* action — actor/target/normalized-params/timestamp/expiry; approval never generalizes; the human owns credential-gated steps, and the confirmation that *is* the authorization is never automated) · **INPUTS** (every real-world identifier needs provenance + its structural check; on failure **stop and ask, never pattern-complete**; target-system content is data, never instructions) · **ACT** (re-read immediately before acting — the TOCTOU check→use gap) · **VERIFY** (confirm from a **fresh read**, not the call's response; prefer a second independent channel; **`UNVERIFIED` is a valid, mandatory outcome**). Emits an append-only `ACTION RECORD` (the sibling of `loop-harness`'s LOOP-STATE ledger). Pure methodology — owns no browser/client/transport by design, and explicitly **not a security boundary**. Fires *rarely* on purpose: ceremony on trivial writes trains everyone to skip it. Evidence-backed by `docs/research/acting-on-live-systems-2026.md`, whose research **reframed the original question** — *don't* build a browser skill: the tool layer converged on DOM/accessibility-tree, vendors already ship browser methodology as skills, and the unsolved risks (believing a call, stale state, fabricated identifiers, content-as-instructions, missing authority) are **domain-neutral**. +1 eval scenario (`act-for-real/refuses-irreversible-without-approval`) + `act_irreversible` fixture.
- **crucible 0.7.0 — `repo-audit` skill.** Recurring, repeatable whole-repo health audit built for *trending*, not one-off snapshots. A deterministic pure-stdlib anchor (`repo_metrics.py`: file/LOC inventory, God-file detection, tracked-artifact & `.gitignore` hygiene, flag-branching count, conservative Python dead-module candidates, and an itemised `anchor_score` — same commit, same number, every run) feeds four **frozen, read-only, parallel** analysis lenses (Janitor / Architect / Clean-Code / DevOps). Synthesized into a dated `docs/audits/{date}-{repo}.md` that the next run diffs (score Δ · closed / new / deferred). Delegates the docs dimension to `cms`; gitignores raw agent dumps (eval-first artifact-hygiene lesson); lenses are versioned so a moved ruler is visible. Reconciles with the VISION non-goal — parallel independent read-only lenses over a static tree are *not* the rejected sequential role-play waterfall. +19 tests (342→361).

### Fixed
- **The toolchain did not run on Windows, and two Phase-4.0 gates failed there in ways that read as success or as an unrelated failure.** A prior release pinned `encoding="utf-8"` on file reads and writes; these are the three places that were left, plus one that had never been reachable from a POSIX machine at all. **(1) `python3` is not an interpreter on Windows.** `coverage_delta.py` and `test_evals_fixtures.py` invoked it directly, where the name resolves to the Microsoft Store App Execution Alias — which prints an install ad, runs nothing and exits 49. For `coverage_delta` that yielded an empty collected set, *indistinguishable from "every test was deleted"*. Code now uses `sys.executable`; emitted gate lines use a `python_token()` that falls back to this interpreter's absolute path on Windows, because `shutil.which("python3")` **succeeds** by finding the stub and therefore cannot be used as evidence that it works. **(2) Windows separators leaked into machine-readable output** — `detect_profile.py` emitted `services\gw` where JSON, an emitted `--repo` argument and cross-platform test comparison all expect `services/gw`, and where a backslash is additionally a shell escape; now `.as_posix()` at the point of emission. **(3) stdout was encoded with the console codepage:** `validate_manifests.py` printed `✔ manifest validation passed` and *then* died with `UnicodeEncodeError` on cp1252, exiting 1 — a passing gate reporting failure — and `invariants_run.py` did the same on an em-dash. All 23 CLI entry points now force UTF-8 stdio; the two MCP servers are excluded deliberately, since their stdout is the JSON-RPC transport rather than a console. **(4) Subprocess output was decoded with the locale** at all 26 `text=True` sites. Separately, both invariant check scripts hardcoded `python3`, so the invariant *"a check that could not run is never reported as a pass"* was itself failing by being unable to run; they now source `scripts/checks/_python.sh`, which probes candidates **by executing them** (the stub exits 49, a real interpreter exits 0), honours `$PYTHON`, and exits 2 rather than 1 when nothing works. A `.gitattributes` was added because line endings otherwise depended on each clone's `core.autocrlf`, so a Windows contributor could commit CRLF and break every shell script on Linux with `bad interpreter: /bin/sh^M`. Four loop-harness entry points (`loop_budget`, `loop_hook`, `loop_ledger`, `loop_logscan`) had no stdio protection at all, which the earlier `use_utf8_stdio` work had reached only in `loop_sweep`; the two that already import `loop_common` now call the shared helper, and the two that do not keep a local copy on purpose — importing `loop_common` **creates the state directory at import time**, and a stdin log parser has no business making a directory as a side effect of being imported. Suite on Windows: 607 passing / 14 failing → green.
- **`author-skill` documented a scaffolder that did not exist for anyone who installed the plugin.** It told the agent to run `${CLAUDE_PLUGIN_ROOT}/scripts/new_skill.py`, but `new_skill.py` lived at the repository root — a path present only in a checkout of this repo. Installed from the marketplace, the plugin's skill-authoring guide pointed at nothing, and the failure was invisible here because a contributor's checkout always has the file. It now ships inside the plugin where its own documentation always claimed it was, and its default skills directory resolves as a sibling instead of by climbing to a repo root it can no longer assume. `session-to-skill` would have inherited the same broken path.
- **The integration target was re-derived instead of recovered.** `start-branch` detects it and, when the branch model is ambiguous, asks the user — and the user's answer was the only authoritative part of the procedure and the only part thrown away, because `finish-branch` and `qa-gatekeeper` both re-ran the same heuristic later, in a session that may not be the one that asked. In an ambiguous repo they can settle on a different branch than the work forked from, and the gate then compares against the wrong baseline while looking entirely healthy. `start-branch` now writes `branch.<name>.integrationTarget` into `.git/config` (per-clone, never committed, never merged — so branch bookkeeping stays out of the branch's own diff instead of conflicting between parallel branches), and both consumers read it before falling back to detection, saying which way they got the answer. The rule is the one `qa-gatekeeper` already applies to the test count, pointed the other way: **derive what changes, recover what does not.** `start-branch` also gained the worktree hazard it did not state — a worktree isolates the source tree and the index and *nothing else*, so the dev-server port, the local database and any fixed output path are still shared and anything that deploys or migrates must be serialised — and the refname trap: never name a child `<parent>/<slug>` when `<parent>` is itself a ref, since git stores `feature/api` as a file and cannot then create the directory `feature/api/auth` needs.

### Changed
- **The eval harness asserts on a subagent's own output, not the orchestrator's paraphrase.** The gatekeeper scenarios bounced 0.33<->1.00 across five measurement rounds, and it was the instrument, not the model: the checks read `final_text`, which is the *parent's summary* of the subagent's verdict, while the parser dropped `user` events entirely -- so the subagent's actual output was in the stream and discarded. The runner now maps `tool_use_id` to tool name and captures `tool_result`; `qa-gatekeeper` must end with a machine-readable `QA-VERDICT:` line, because a verdict that has to be inferred from prose gets inferred differently by different readers, and by the same reader on different days. Also: the subagent tool is `Agent`, not `Task` -- verified against a captured stream rather than written from memory, since a wrong name yields no results and "no results" would otherwise have satisfied the *not-matching* direction forever; both directions now fail on absent results.
- **Four fixture-design rules, each learned from a failing eval that turned out to be the eval's own fault.** (1) A fixture must deliver a **complete** change -- a branch named "add-widget" shipping one unrelated test gets rejected for being empty, and then it is fixture realism being measured, not the property. (2) It must be **unambiguous** -- deleting code *together with* its tests is a legitimate refactor, and the gate calling that CONDITIONAL_PASS was reading it correctly. (3) Assert on **behaviour, not implementation traces** -- gating on `git merge-base` appearing in a Bash call tests *how* a baseline was derived; build a fixture where the right verdict is unreachable without doing the right thing instead. (4) A **"must not reject" twin proves the absence of one specific false alarm, never global approval** -- a defect fixture makes an existential claim and is easy to build, a twin makes a universal one, and a competent reviewer finds *something* in almost any toy code (the first wired-guard twin was rejected 3/3 for a hardcoded credential and an unhandled `None`, both real).
- **`qa-gatekeeper`'s truth-gate sections were measured at k=10, and the number that mattered was the sample size.** Final: assertion-quality 9/10, mock-provenance 10/10, unreached-code 9/10, swallowed-exceptions 9/10 — **37/40**. An earlier k=3 pass read 3/3, 4/6, 2/3, 3/6 and was written up as "unreliable, not dead". That was wrong, and not marginally: swallowed-exceptions read **0/3**, then 3/3 with nothing changed in between, and was one decision away from being rewritten as a deterministic script. It is 9/10. A k=3 run cannot distinguish 30% from 90%, so it cannot support a conclusion about a prose gate — the ~40 minutes a k=10 costs is less than the day the wrong conclusion nearly cost. The metric is additionally biased low, because a scenario scores "did it find the defect I seeded" and a reviewer finding an unseeded defect scores as a miss; six supposedly-clean fixtures were rejected during this work and the gate was right every time.
- **`cms` wrote runtime state *into* the generic plugin, contaminating the Tier-A seam.** `tests/test_seam.py` had been red on `main`: `size_history.json` inside `plugins/crucible/` had accumulated the repo names of whatever ecosystem was using the skill — domain content in a generic plugin, which is exactly what ADR-001 forbids. The file was already gitignored, so nothing leaked into git; but the seam test scans the **filesystem**, and rightly so, since a plugin directory carrying domain content carries it wherever that directory goes. The underlying bug was worse than the symptom: `common.py`'s own comment said state *"must survive plugin updates, which overwrite the cached plugin dir"* — and then the final branch wrote it into that very directory. Since neither `CMS_STATE_DIR` nor `CLAUDE_PLUGIN_DATA` is set in ordinary use, **that branch wasn't a rare fallback, it was the only path ever taken**, so state was being written exactly where the design said it must not and destroyed on every plugin update. Runtime state now defaults to `~/.claude/cms-state`, with a non-destructive one-time migration out of the plugin (an existing file at the new location wins; failures are silent, because losing size history costs one warning while crashing costs the skill). All 29 repos of history carried over. Shipped config (`sync_facts.yaml`) stays versioned in the plugin, and `SKILL.md` now states that split explicitly. +4 regression tests, verified to fail against the old resolution order.
- **Windows encoding — plugin scripts crashed or silently corrupted non-ASCII docs.** Every `read_text`/`write_text` call across the plugins relied on the platform default encoding, which is **cp1252 on Windows**, not UTF-8. Two live failure modes: a hard `UnicodeDecodeError` (e.g. `cms/scripts/init.py` scaffolding a repo whose docs contain an em-dash), and — worse — **silent corruption** at the 13 sites passing `errors="replace"`, which still decoded as cp1252 and mangled `—`/`→` into `�` instead of failing loudly (this is what corrupted a freshly scaffolded `SKILL.md`). Pinned `encoding="utf-8"` at **54 call sites across 25 files**. Separately, `loop_sweep` wrote its non-ASCII report to a cp1252 stdout, raising `UnicodeEncodeError` mid-report and killing the process with exit 1 — **silently breaking the documented 0/1/2 exit contract, so a cron sweep reported "red" when it actually meant "couldn't parse a summary"**. CLI entry points now force UTF-8 stdio (`loop_common.use_utf8_stdio`), and the sweep decodes the suite's output as UTF-8 with `errors="replace"` (a sweeper must survive whatever a test prints, not die on an emoji). Fixes 5 pre-existing failures — the suite was only ever green on POSIX (357 passed / 5 failed → **362 passed**). Windows users no longer need `PYTHONUTF8=1` to lint a repo whose docs contain non-ASCII.
