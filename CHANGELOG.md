## [Unreleased]

### Added

- **crucible 1.1.0 — the `ai_summary` cap now bounds the table, not just the row.** The per-document cap (`AI_SUMMARY_MAX_BYTES`, 1500) bounds one row of the triage routing table. What a triage pass is actually charged is the **sum of every row**, and that grows with the corpus while each summary stays comfortably legal — fifty documents at the cap is a table costing more than the reads it was built to replace, with every individual check passing and the mechanism defeated anyway. The two are not one check at two thresholds: one bounds a document's contribution, the other bounds the mechanism's own overhead, and only the second grows when nobody edits anything. `check` now reports the aggregate against `AI_SUMMARY_AGGREGATE_WARN_BYTES` (20000, roughly 5k tokens — the point past which the table costs more than opening the two or three documents it would have saved you from opening). A Warning, never an Error: nothing is malformed, the corpus has outgrown a flat table, and the fix is splitting it by directory or archiving what should not still be indexed rather than shaving bytes off every summary. Calibration from real use rather than taste: hephaestus's own 11 summaries total 5,508 bytes, so the threshold permits roughly 40 documents at this quality. Verified against a 40-document fixture at ~1200 bytes each — one aggregate warning, **zero** per-row warnings, which was the falsifiable half.

- **hephaestus can now route on its own documentation.** `triage` existed so a lookup reads one body instead of several, and it could route on **2 of 10** documents — the standard applied outward more thoroughly than inward. All ten now carry an `ai_summary`, including `LESSONS_LEARNED.md`, which is precisely where an agent should be sent and previously could not be. `cms/SKILL.md` also went from **5 tokens** of headroom against its 3000-token budget to 148, by moving the retrieval rationale to `references/retrieval.md` and cutting a block catalogue that its own reference already owned — five tokens from the gate meant the next cms edit would have failed `skill_lint --strict`, and the tempting fix at that point is raising the threshold, which is the anti-pattern the skill names outright.

- **forge-unity 0.1.0 — the marketplace's first engine-specific plugin, and deliberately its thinnest** ([ADR-003](docs/decisions/003-decompose-game-development-support-into-a-growing-crucible-and-one-thin-engine-adapter.md)). The question was whether to extract a game-development plugin *set* from a private Unity project's 13-skill harness. The answer is no, on local evidence rather than taste: that game's first-generation repo already shipped exactly such a set — two Unity subagents, three path-scoped rule files, three knowledge skills, a compile hook, a file guard, a state-injection hook, a registered MCP server — and the successor repo carried almost none of it. What survived and grew was **verification**. The engine knowledge layer is the part that already failed to survive once, and it is also the only lane the public marketplaces are saturated in. So forge-unity ships **no engine reference material**, and carries two things instead. `adapter.py` solves the problem that a published plugin cannot ship the commands that matter — start a run, drive input, dump a trace, capture a sheet are implemented in a project's own source under names only it uses — by inverting the seam: the plugin owns an engine-neutral vocabulary and a detector, the project owns the implementation and declares the mapping in `.forge/adapter.json`, so a Godot adapter becomes a config file rather than a rewrite of every skill. An unimplemented verb exits 3 and emits **nothing**, because the failure this must never have is a plausible guess: a well-formed command name that runs nothing and reports success. `asset_integrity.py` checks the parallel bookkeeping Unity keeps and never reports — source it never imported (so it does not compile, does not appear in menus, cannot be attached), `.meta` records whose asset is gone, components serialised as `m_Script: {fileID: 0}` — none of which fails a build, a test, or a diff review. Run against a real Unity project it found a genuine broken script reference; its unwired check reported 29 until narrowed to types Unity can actually attach, since an interface or enum is referenced from code and never from a scene, and 29 → 1 is the difference between a report someone reads and one they skim. Unwired stays a *question* and does not decide the exit code, because deleting on that signal alone is how a feature still being built gets removed.

- **crucible — the gate stops assuming a test suite exists.** `finish-branch` gated on one sentence: "tests green, no regression against the branch point". In a repo with a suite that is exactly right; in one without, the sentence has no referent, nothing fails, and the gate reports success — "nothing failed" and "it works" are different claims. That is not an edge case: a game, a notebook pipeline, an infrastructure repo and a design system all verify by *observation*. `evidence_gate.py` reports what `.crucible/evidence.json` declares, narrowed to the classes a given diff triggers, and **reports without ever judging** — a script that decided whether evidence existed would have to accept a claim as proof. Backward compatible by construction: no declaration plus runnable gates yields the implied class, the test run, unchanged. A present-but-malformed declaration exits 2 and never falls back to a weaker requirement. The verdict becomes **three-valued — `pass` / `fail` / `could-not-check`** — because folding the third into `pass` is how an unverified change acquires a green tick, and folding it into `fail` turns a missing capability into an accusation. Two independent sources demanded that third state: the verified-tool-call literature returns True/False/**Unknown**, and the `cpp26-adapter` plugin separates a genuine bug from `compiler-lag`.

- **crucible — `sync-branch`**, the missing skill between `start-branch` and `finish-branch`. Dry-runs with `git merge-tree` before taking the merge, refuses a dirty tree (the checkpoint, not the merge, is what protects work in progress), and syncs target → branch only, so a bad resolution never becomes the baseline every other branch copies. Documented as a **trigger, not a position**: one real branch went 0 → 17 → 20 → 2 commits behind in a single session, once mid-gate, and no fixed slot in an ordered workflow survives that. It carries the classification table including the row that matters most — *the target generalised what you extended* — which auto-merges cleanly into something wrong.

- **crucible — `act-for-real` gains the RETRY gate it was missing.** The skill already treated verification as a hard gate but said nothing about what to do when an attempt's outcome is *unknown*, which is precisely where duplicate side effects come from. A timeout is silence about the outcome, not news of a failure: the channel that reports and the channel that acts are separate, so the effect may already exist. Verify before every retry, carry a **deterministic** idempotency key (a fresh random one per attempt is not an idempotency key — it guarantees the far side treats each attempt as new), and treat repeated ambiguity as `UNVERIFIED` rather than another attempt. Published work on verified tool calls: blind retry decayed from 92% to 64% task success while gated retry held 100%, and duplicate side effects fell from as high as 72% to at most 20% — with an ablation showing **verification, not retrying, accounted for most of the gain**. The companion `references/blocked-signal.md` covers the case where the *environment* is the unreliable part, and reconciles it with `could-not-check` so a session cannot emit one and record the other.

- **Cross-agent installation.** Claude Code consumes this repo as plugins; Codex and Pi have no plugin container and discover skill directories instead. `scripts/install_skills.py` links the skills into `~/.claude/skills`, `~/.codex/skills` and `~/.pi/agent/skills`, and **prints what cannot travel** — slash commands, subagents, hooks, MCP servers — because a skill that silently loses its hook looks like it works while the guarantee is gone. It links rather than copies so one fix reaches every agent, and where the platform refuses symlinks (Windows without Developer Mode) it copies and says so; a silent copy is the drift it exists to prevent. All 17 skills were already inside the frontmatter set all three agents honour, so this documents and enforces a property that already held rather than changing one.

- **crucible 0.15.0 — `curate`, the pass that maintains the fabric instead of a feature.** This repo had exactly one workflow, and it builds things. Nothing maintained them — and the gap has a name and a measured cost in the literature: **skill technical debt** (redundancy, missing validation, interface drift, stale implementations), none of which breaks a skill locally, all of which degrades retrieval and composition later, and none of which any single diff introduces. A rule-based maintenance loop over a 200-skill library beat the strongest baseline by roughly nine points at essentially no per-task model cost, because the diagnosis is *counting* rather than judgement — so `curate` runs the scripts first (`skill_lint`, `cms triage` + `check`, `repo_metrics`, `predictions`, `invariants_run`), reads five library-health dimensions from what they return, audits the range since the last pass with `refactor-audit`, settles any prediction whose check has run, and produces a backlog ranked by *cost of leaving it* against *cost of fixing it*, split into what an agent can fix unattended and what needs a human decision. It states the merge rule exactly — merge only when two skills take the same inputs **and** produce the same artifact, otherwise sharpen the descriptions — because "these feel similar" is how good skills get merged. Cadence, not per change: a maintenance routine that fires too often is one people skip entirely.
- **crucible 0.15.0 — decision observability: `predictions.py`.** Every change in a repo was justified at the time; what a repo never accumulates is evidence about whether the justifications were *right*, because the prediction is made in a commit message and the outcome arrives weeks later somewhere else, and nothing puts the two side by side. The result is a codebase where every decision looked sound and the overall direction cannot be evaluated. A prediction is now recorded before the change lands with the check that would settle it, and the outcome is appended beside the original words later. The format enforces two rules rather than requesting them: a prediction with **no `--check` is refused**, since a claim that cannot be wrong is graded correct in hindsight every time; and a recorded claim is **immutable**, because editing it to match the result is simultaneously the natural move and the one that destroys the record. `unclear` is a first-class verdict — forcing a binary answer onto an ambiguous outcome is how a ledger becomes fiction. `list` says out loud when nothing has ever been recorded wrong, because a ledger with no misses is far likelier to be measuring nothing than describing perfection. Wired into `develop` (recorded after the Phase 2 gate, settled in Phase 6) and into `curate` Phase 4, and seeded with three falsifiable predictions about this release's own changes. Adapted from the observability-driven harness-evolution result where pairing each edit with a self-declared, later-verified prediction lifted pass@1 on Terminal-Bench 2 from 69.7% to 77.0%, past a human-designed harness at 71.9%.
- **Eval coverage for `refactor-audit`, `curate` and `skill-craft`.** The previous release shipped a breaking rename, two new skills, a command and a hook with zero behavioural coverage. Each new scenario asserts a discipline its skill states and could plausibly break: `refactor-audit` is asked to *"just fix it"* and must still rank and report while changing no code (a discipline about not fixing only means anything when the user asked for the opposite); `curate` must **run** its deterministic pass, asserted by matching `skill_lint.py` in the tool trace, which is the one thing separating the workflow from an agent reading files and forming an impression; and `skill-craft` must **decline** a session containing no reusable skill, which is the harder behaviour because writing the file always feels more helpful. Two fixtures back them: `refactor_duplication` carries a byte-identical paste so a finding about it is provable by diff rather than asserted, and `skill_library` is deliberately **clean** — seeding an obvious defect would let a run score by noticing it without ever running the check that was supposed to notice it, measuring eyesight rather than the workflow. All three were verified by running them (2/2, 1/1, 3/3), not by writing them.

### Changed

- **crucible is 1.0.0 — the `0.x` breakage licence is spent deliberately, not by drift.** Under SemVer, `0.x` means "a minor bump may break you", and crucible has used that: 0.15.0 renamed two skills out of existence. Declaring 1.0 gives that licence up on purpose, because the thing consumers actually depend on has stopped moving — 17 skills across 6 plugins, 839 tests, an invariant set with executable checks, and a marketplace clone on at least one machine that tracks `main` and reloads every session. The version was becoming a poor description of that: a tool people rely on daily reading `0.16.x` understates the commitment already being made to it in practice. **What 1.0 promises** is the surface a consumer binds to: skill names and their invocation forms, the script paths and CLI contracts under `skills/*/scripts/` and `scripts/`, the documented exit codes, the frontmatter schema, and `.crucible/evidence.json` + `.forge/adapter.json`. Renaming or removing any of those now costs a **2.0**, which is the entire point — the constraint is the promise. Two breaking changes were deliberately folded in *before* publication rather than deferred: `predictions.py record` gained a required `--baseline`, and a missing `--check` or `--baseline` now exits 1 (refused) instead of argparse's 2, which this script reserves for "could not determine". Both would have cost a 2.0 a day later; the window for shaping what 1.0 *is* closes the moment it ships, and it had not shipped. **What it does not promise**: prose, rationale, references, or the internal shape of a skill's instructions, all of which should keep moving, since a stability guarantee over wording would freeze the part most worth improving. Versions here remain **per-plugin** ([tags are `<plugin>-v<x.y.z>`](CLAUDE.md)), so this says nothing about the others: `forge-unity`, `mcp-starter` and `sqlite-readonly` stay at `0.1.0`, `second-brain` at `0.3.0` and `deck-builder` at `0.1.1` — each is genuinely still `0.x`, and levelling them to match would be the version number lying in the opposite direction.

- **crucible 0.15.0 (BREAKING) — `author-skill` and `session-to-skill` merged into `skill-craft`.** They were the one genuine redundancy in the library: different starting points (an intention someone already had, versus a transcript of what just happened) producing the same artifact by the same rules — the shape the retrieval literature calls **same-capability ambiguity**, where a model must choose between two skills and the choice does not matter, so it is made arbitrarily. This repo's own precedent already argued for it, since `cms` carries eight commands and `second-brain` three actions as one skill each. `skill-craft` has three modes: `author` (scaffold, then coach — handing back a stub is the easy half), `distil` (generalise the process, never snapshot the task), and `lint`, which is where `skill_lint` finally lands after existing as a CI step no skill referenced. The refusal is now shared and stated first, where both modes need it: most sessions contain no skill and most "wouldn't this be useful" ideas are not one either, and shipping them costs a routing decision on every future session — the cost this change is paying down. The nine authoring patterns moved to `references/patterns.md`, which is pattern 7 applied to itself. `docs/decisions/001` and the research notes deliberately still say `author-skill`: an ADR records what was decided when it was decided, and editing one to match a later rename falsifies the record.
- **`skill_lint` now runs at the moment a SKILL.md is written, not only in CI.** Placement was measured here once already — asking an agent to run a check caught a defect 2/6, having the harness run it caught 3/3 — and a CI-only lint was the first placement. The severity split is the part that matters: an **ERROR blocks** the write (malformed frontmatter, a missing name or description, a name disagreeing with its directory — each makes a skill load wrongly or not at all, each is cheap to fix in the moment, none is a judgement call), while a **WARN prints and allows**, because blocking a write for being forty tokens over budget makes adding a section in two edits impossible and a gate that fires mid-thought is one people disable. Cross-skill overlap is deliberately excluded: it is a property of a pair, needs the whole corpus, and cannot be acted on in the edit that triggers it. The hook judges the content the write *would produce* rather than the file on disk — checking the latter tests the document the edit is about to replace and passes exactly when it should not — and fails open on anything it cannot determine, since a broken hook would otherwise be a broken editor. `skill_lint.py` moved into the plugin for the same reason `new_skill.py` did.
- **`cms triage` is now wired where it was already being done by hand.** `refactor-audit` step 2 instructed the agent to read the repo's context and decision records, and `develop`'s research phase told it to explore — both now start from the routing table, which is what `triage` was built for and which neither was using. Searching by opening candidates costs the full text of everything you opened and were wrong about, so orienting scaled with the corpus rather than with the answer.
- **A skill-quality gate, and a duplication metric that counts passages instead of windows.** `validate_manifests.py` proves a plugin is well-formed and `test_seam.py` proves it is domain-free; neither can see the two ways a skill *library* decays — a `SKILL.md` quietly outgrowing the context budget it is charged against on every session that loads it, and two skills drifting into saying the same thing, which no single diff introduces and so review cannot catch. `scripts/skill_lint.py` checks frontmatter conformance and naming (ERROR), token budget, unsanctioned keys and cross-skill overlap (WARN); `--strict` makes warnings fail and is what CI runs. The metric is deliberately **not** a shared-shingle count, and the reason is the first thing it found: sliding 12-word windows over *one* shared sentence yields nine or ten "shared shingles", so `act-for-real`↔`flag-gate` (both stating that a flag in front of a one-way migration is not a kill switch) and `grill-me`↔`spar-with-me` (both drawing the deciding-versus-being-talked-out-of-it distinction) were reported as nine and six defects. Both are the **"pairs with" convention working as intended** — deliberate cross-references, each skill telling the reader which sibling to reach for. So overlapping windows are merged back into maximal runs and the check reports distinct passages, warning on two or more runs or a single run past 30 words (a pasted paragraph, not a cross-reference). The prose was right; the measurement was wrong, and lowering a threshold instead would have hidden that. The one real finding is fixed: `cms` was ~3257 tokens, and its `Rendered architecture view` section was a 14-bullet summary of the 19 KB `references/architecture-views.md` sitting beside it — it now keeps the four rules an agent could violate without opening the reference and sends the schema catalogue there. CI also gains a **`cross-platform` job** (macOS + Windows), added as a *separate job* rather than a matrix on `checks`, because branch protection requires a status check named exactly `checks` and matrixing renames it to `checks (ubuntu-latest)`, detaching the rule with nothing appearing to break. +20 tests.
- **crucible 0.14.0 — `refactor-audit` and `session-to-skill`.** Two gaps named by what the library already had. `repo-audit` says outright that it is not for reviewing a single change and code review looks for defects, so nothing audited **one body of work** — a range, a branch, the working diff — for what it would take to reach production quality; `refactor-audit`'s centre of gravity is the *ranking* (a flat list of thirty observations gets skimmed and the two that mattered go with it) and the split between what an agent can fix unattended and what needs a human decision, since those are read by different people. Its two rails: every finding names the standard it fails, and **the project's own conventions outrank generic best practice** — an audit that re-litigates a settled decision gets discarded wholesale, taking its correct findings with it. `session-to-skill` runs the other direction from `author-skill`: that one starts from an intention someone already has, this one starts from a transcript and must first decide whether there is a skill in it at all, generalising the process rather than snapshotting the task, with refusal as the honest default — a library of thin near-duplicate skills taxes every future routing decision. Both pass `skill_lint --strict` against the existing thirteen, which is why the linter was built first.
- **`cms triage` — retrieval on summaries, not bodies.** The `@path`-versus-plain-link rule governs what loads unconditionally; nothing governed what loads *while you are still looking*, which is the half that grows with the corpus. Searching by opening candidates costs the full text of everything you opened and were wrong about — free at ten documents, most of a context window at fifty. Documents may now declare an optional `ai_summary` and `triage.py` prints a routing table (path, status, summary; never bodies). Three properties keep it from becoming the cost it removes: a summary says what a document **is and when to open it**, never what is in it (the second kind is a second copy that goes stale on its own schedule, which is worse than none because it is trusted); it is **bounded** at 1500 bytes and re-read on every pass, so `check` warns past the cap — a Warning, since the document is still valid, it has just stopped earning its place in the index; and it is **optional, with unsummarised documents listed anyway**, marked and sorted last, because an index that silently omitted them would route confidently around the part of the corpus it cannot see. Optional is deliberate: requiring it would invalidate every document already on this schema, and a summary written to satisfy a linter is worse than none. Adding it pushed `cms` back over the 3000-token budget the same release introduced — the gate working, not obstructing — so `Skill principles` (306 tokens of provenance, read when deciding whether a rule should change, which is rare) moved to `references/design-rationale.md` and the shared-state mechanics to `references/shared-state.md`. +6 tests.
- **second-brain 0.3.0 — the vault health report is computed, not read for.** `review` asked four questions that are pure counting — what links to nothing, what nothing links to, which links resolve to no note, which tags are variants of each other — and answered them by having the model read the whole vault: cost proportional to vault size, untestable, and a slightly different answer each run, so a vault could never be trended. A health report you cannot compare with last month's is a mood. `scripts/vault_graph.py` does the counting in one pass (exit 0 = report, 2 = could not determine — an empty vault is not a clean bill of health), parsing what Obsidian actually does rather than what wikilinks look like: aliases, headings, block refs and embeds all resolve to the same target, links inside fenced or inline code are examples rather than links (without which any note documenting `[[wikilink]]` syntax manufactures broken links), and a link resolves by note *name*, not only by path. Two deliberate refusals: it pairs tags differing by case, separator, plural or typo and will **never** pair `#ml` with `#machine-learning` — they share no substring and no string metric finds them, so the report names the limit and leaves that judgement to the model, where propose-then-confirm requires it to sit; and `_meta/tags.md` is excluded from the note set, since counted as a note it is a permanent orphan and its declarations turn every approved tag into a phantom "used once", burying the real singletons. +18 tests.
- **crucible 0.13.0 — `cms site`: a multi-repo documentation site built from the markdown that already exists.** `site.py <root>` assembles the docs living next to the code into one navigable site, driven by a `site.toml` that lists repositories **and nothing else**. It authors nothing — every page is an existing file rendered through the same engine the standalone pages use, so diagrams, tours and plots work unchanged. The rule that makes it generic across repos without per-repo configuration is **a page exists if its sources exist**: a repo with no `DEPLOYMENT.md` has no "Running it" entry and no dead link pointing at one, and dropping the file in later is the whole of the work. There is no manifest to update and therefore **no way for the nav to promise a page nobody wrote**. Documents that no named section claims still get pages of their own — without that the site is a curated subset that *looks* complete while quietly dropping most of a repo. The renderer was generalized to match: it renders **any** document rather than only `ARCHITECTURE.md`, and titles now come from the document itself (frontmatter `title`, then a map of cross-industry conventional filenames — README, CHANGELOG, SECURITY — then a readable form of the filename), so no caller has to declare what a document is. That generalization exposed a real bug: `md_path.parents[1].name` assumed every document lives under `docs/`, so a root-level `SECURITY.md` reported the **parent directory of the repo** as its repo; the repo root is now threaded through explicitly. Search indexes every page including the unclaimed reference documents, and holds the whole index **inline on one page** rather than fetching it — a fetch is simpler but would make that page the only one on the site requiring a server to behave a particular way, and every other page opens from a `file://` URL. Highlighting **walks the string instead of compiling a `RegExp` from the query**, because building a pattern out of whatever a reader typed means escaping every metacharacter correctly, and getting that subtly wrong is how a search box starts throwing on a bracket (verified with a `[bracket` query, which now returns "nothing matched"). Topology diagrams gained cross-repo links: a node whose **exact** label matches a configured repo name offers "open &lt;repo&gt;" in the readout — deliberately strict, since anything looser starts inventing links, and a document can set `href` by hand for what the matcher will never guess. It is a readout entry rather than a click target, because clicking a node already means "inspect this" and silently changing that to "navigate away" is a trap. Finally, the bug worth the most: `docs/README.md` and `docs/lore/README.md` both slugified to `ref-readme`, so the second **silently overwrote** the first — nothing failed, nothing warned, and the only trace was a page count of 167 against 166 files on disk. That is the worst shape a bug can take in a documentation site: it looks complete and one document is simply gone. Slugs now carry their path under `docs/`, and a duplicate **raises instead of writing**. `tests/test_cms_render.py` at 143 collected.
- **crucible 0.12.0 — `spar-with-me`, and the discovery that `grill-me`'s problem was routing, not tone.** The complaint was that `grill-me` felt too aggressive to reach for. It was not miscalibrated on intensity — it was miscalibrated on **lifecycle stage**: every phase in it attacks a position, which only works if the user *has* one, and its description ended with *"or needs a thinking partner on a non-trivial choice"* — a clause that pulled it into exactly the half-formed-idea moments it is worst at, then grilled the user for not having a thesis. So the fix is one line of description plus a sibling, not a rewrite: **`spar-with-me`** takes the forming stage, `grill-me` keeps the commit stage and its falsifiable-tripwire close (which nothing else in the plugin does), and each names the handoff to the other — which also gives `grill-me` its first inbound edge. Three properties carry the new skill. **Research is unconditional and two-sided** — internal *and* web, every time, never a judgement call: web-only confidently proposes what a repo already rejected for reasons that still hold, internal-only re-derives what the field settled years ago, and where the two disagree is usually the most valuable thing in the session. **Read-only is structural, not worded** — fan-out goes to `Explore`/`Plan` agents that carry no write tools *by construction*, because "change nothing" is stated at turn 1 of a conversation that is by nature long and multi-turn, and the same placement-beats-wording result that moved the Phase 4.0 checks applies to any constraint that must survive twenty turns. And the anti-sycophancy rule is given a **falsifiable form** — *change position on new evidence or a new argument, never on restated preference or displeasure, and say which just happened* — because "be honest" is the same class of instruction as the pushback it must withstand and loses to it on recency; models flip correct→incorrect on user rebuttal roughly 1 in 7 times. The rule is deliberately indifferent to the *direction* of an update and picky only about its *cause*, since a rule that made positions sticky would just be wrong more stubbornly. Reconciled against the VISION non-goal exactly as `repo-audit` is: one conversational agent with independent, read-only, parallel research fan-out is not the rejected role-play waterfall. Evidence in `skills/spar-with-me/references/honest-take.md`. +3 eval scenarios (21 → 24) and a `spar_idea` fixture whose repo-local ADR contradicts the textbook web answer — so the internal-research check cannot be satisfied by plausible-sounding prose.
- **A test for the eval README's scenario table.** It had drifted silently — rows were added to the suite and never to the table — and nothing caught it, including a prior claim that it was already checked. `test_readme_table_lists_every_scenario` asserts **set equality in both directions**, since a stale table understates *or* overstates coverage and a reader cannot tell which. Verified to fire on a removed row rather than passing vacuously. Alongside it, `test_every_scenario_is_wired_correctly` now asserts the **named artifact exists**: a scenario pointing at a renamed or deleted skill still runs, it just invokes nothing — and a run that invokes nothing satisfies every "must not do X" check perfectly, a silent false pass in the reassuring direction. Renaming this very skill mid-review is what surfaced the gap. Scoped to skip plugin-level scenarios (`skill == plugin`, e.g. the `sqlite-readonly` MCP server), where the existing plugin-directory assert is already the right check.
- **crucible 0.10.0 — `archflow`, a serpentine layout for pipelines, and the check that catches the omission.** `/cms render` grew a fenced ` ```archflow ` block: it **walks an existing `archview`** rather than redrawing it, so "what is here" and "what happens" cannot drift apart — select a flow, everything off its path dims, prev/next steps through it, deep-linkable as `#flow=&step=`. Every reference is resolved **at build time** and a dangling one fails the render, because `check_arch.py` only reads the emitted SVG where a broken picker and a working one are geometrically identical. The enabling change was DOM identity: nodes, edges and groups now carry figure-scoped ids, with **edge identity on a wrapping `<g>` and never on the `<path>`** — `RE_PATH` requires `d=` immediately after `class=`, so an attribute between them stops it matching *any* connector and every page would pass while checking zero edges. A view that is one unbranched chain of 4+ steps is laid out **serpentine** (left to right, wrapping, alternate rows reversed); through the layered engine a seven-step pipeline is a column ~800px tall, strictly worse than the numbered list it replaced — found by screenshotting the output, not by reading it. And `check` now warns when a doc holds 4+ sequential steps as prose with no `archflow`: that omission went unnoticed for weeks because a list is valid markdown and the page rendered fine, so nothing that verifies *the page builds* could see it. Craft: light theme via `[data-theme]` stamped before first paint, `@media print`, a generated legend in fixed semantic order, per-node `role="graphics-symbol"` + `aria-label` (not `<title>`, whose native tooltip fights the flow caption), and a visually-hidden text-alternative table built from the model that was already structured. Contrast: `--faint` sat at **2.85:1** on `--void` while carrying every table header, figure caption and 8px diagram sub-label; lifting it alone would have collapsed it into `--mid`, so the ramp is re-spaced to 5.04 / 8.15 / 14.82. - **The dead-code metric was wrong about live code, and the reason was one regex.** `repo_metrics.py` matched `^\s*(?:from|import)\s+([\w.]+)`, which captures only the module path after `from` — so `from harness import runner, scoring` never recorded `runner` or `scoring`, and any submodule imported the most ordinary way there is became invisible. - **crucible 1.0.0 — the archive rule was measuring the clone, not the document.** `cms`'s archive rule asks "has anyone touched this in 60 days?" and answered with `path.stat().st_mtime`, which does not answer that question at all: git neither records nor restores mtimes, so a fresh clone stamps every file with the checkout time and every document in the repository reads as **zero days old**. The rule therefore stopped firing entirely on CI, on a new machine, and for every consumer who obtained a repo by cloning it rather than copying it — and it did so *invisibly*, because a rule that produces no findings is indistinguishable from a repository that has nothing to archive. `render.py` had already learned this and says so in its own docstring ("git does not preserve mtimes… which fired on the first merge of this tool"); the lesson was never back-ported. It was also **four bugs, not one**: `check.py` decided candidacy from mtime, `migrate.py` re-implemented candidacy independently from mtime with its own duplicated 60-day constant, `migrate.py` derived the `docs/archive/YYYY-MM/` **folder name** from mtime — so after a clone every document ever archived filed itself under the current month, falsifying the archive's own index — and `add_frontmatter.py` **wrote** `created:` from mtime, persisting a wrong date into the file where it feeds `review_in` staleness forever. All four now resolve through `scripts/doc_age.py`, which batches one `git log --format=%x00%ct --name-only --diff-merges=first-parent` for the whole repository (per-file `git log -1` is worse than O(n) spawns, since each walks history from HEAD until it finds a touching commit) and takes the **max** per path, because git's output order is not reliably monotonic. Committer date rather than author date is deliberate: both can be wrong, but author date survives a rebase and over-reports age while committer date is rewritten and under-reports it, and under-reporting is the safe direction for a rule whose action is "archive this". Merges are included explicitly — without `--diff-merges=first-parent` a file whose only change arrived through a squash-merge is invisible to `--name-only`. Where git cannot answer, the age falls back to frontmatter (`last_reviewed_on`, then `created`), and where nothing clone-stable can answer it emits **nothing**; it never falls back to mtime. **Shallow clones are refused rather than trusted** — with `depth=1` every path collapses onto the graft commit and every file reads as changed today, which is the same failure as mtime except now wearing a git costume, so `check` reports the age source as degraded and names the fix (`fetch-depth: 0`) instead of silently producing zero findings. The documented `status: completed` trigger, which `SKILL.md` has always specified and which `migrate.py` has always *written* and never read, is now implemented, so the tool finally consumes the clone-stable signal it was already producing.

- **The tests could not have caught it, by construction.** All three tests exercising the age branch manufactured an old file with `os.utime`, asserting against a filesystem state git never produces — which is exactly why the rule could be completely broken on every clone while the suite stayed green, and why two of them turned red the moment the source changed. **No test of document age calls `os.utime` any more.** A `git_doc_repo` fixture builds a throwaway repository and commits with a real backdated `GIT_COMMITTER_DATE`, leaving the file's mtime at *now* — the precise condition a fresh clone produces. The test that matters most clones a repository and asserts the clone and the original report an **identical** finding set, which is the property the whole change exists to buy and the one no previous test expressed. `migrate.py`, which had zero tests, is now covered, including an assertion that it and `check.py` agree file-for-file — they were independent implementations of one rule and could disagree about the same document. +18 tests (804 → 822 collected).

- **The pytest suite leaked two temp directories per process.** `os.environ.setdefault(var, tempfile.mkdtemp(...))` reads as "use a temp dir only if the caller did not supply one" and behaves as "always create one, then sometimes discard it" — Python evaluates the argument before `setdefault` can decline it. Two per pytest process, never removed; ~490 empty directories had accumulated in `%TEMP%` on one machine over a month. Both calls must stay at import time (`common.py` and `loop_common.py` resolve *and* `mkdir` their `STATE_DIR` at module import, and test modules import them during collection, so a fixture runs far too late), so the fix is a guard-then-create helper plus a `pytest_unconfigure` that removes **only** the directories that process created. `ignore_errors=True` is load-bearing rather than defensive: the Windows CI leg occasionally still holds a handle on `size_history.json` at session end, and a cleanup failure must not turn a green run red.

- **The repository did not run on the Python it promised, and CI could not see it.** `README.md` stated "Python 3.9+" while `site.py` shipped two things that break it: a backslash inside an f-string expression (PEP 701, legal only from 3.12) and `import tomllib` at module scope (stdlib only from 3.11). Neither degrades a feature — both stop `pytest` **collecting**, so the entire suite was unavailable on 3.9, 3.10 and 3.11. CI never saw it because all three jobs pinned `python-version: "3.12"`: the matrix varied the OS and never the Python, so the defect was invisible on all three platforms simultaneously. The obvious guard does not work either — `ast.parse(feature_version=(3, 9))` accepts the pre-fix file, because PEP 701 changed the *tokenizer* and `feature_version` only gates grammar, making the check that looks sufficient the one that fails silently. `scripts/python_floor.py` therefore runs three passes: `tokenize` for f-string constructs, `feature_version` for grammar, and an AST scan for module-level imports of stdlib newer than the floor, where a deferred or `try/except`-guarded import is the correct fix and is deliberately not flagged. Wired as an invariant and as a CI job with a real interpreter matrix (3.9–3.13) — a separate job rather than a matrix on `checks`, because renaming that status check would detach branch protection without anything appearing to break. The site builder now degrades honestly on older interpreters instead of failing at import.

- **`check-public-safe.sh` did not guard against third-party project content**, which matters now that a plugin generalises patterns learned in someone else's repository. It gained a second token group and immediately earned it: it caught that project named five times inside ADR-003, which was de-identified in response. A plugin may carry the lesson; it may not carry the project.

- **`release.sh` could not cut a release from Windows.** It guarded with `command -v python3`, which **succeeds** there by finding the Microsoft Store App Execution Alias — an ad printer that runs nothing and exits 49 — so the guard passed and the next line died. That is the worst place to half-execute a script: a release can end up with a version bumped and untagged. Found by trying to cut `crucible-v0.15.0` from Windows and discovering the documented command does not work; the tag was created by hand instead. This is the same defect class fixed across the Phase-4.0 scripts in the previous release, and it survived because that sweep was scoped to "scripts the gates run" and `release.sh` is not one — nothing checked it, so nothing caught it. It now sources `scripts/checks/_python.sh` (which probes candidates by *executing* them and exits 2 when none work) and routes every call site through `"$PY"`. Guarded statically rather than behaviourally, deliberately: `release.sh` verifies it is on `main` before it reaches the interpreter, so the path cannot be exercised from a feature branch. The check is generalised over every shell script under `scripts/`, verified to fire on a planted `python3` rather than passing vacuously, with the glob itself guarded so an empty parametrize cannot pass silently.
- **CI ran on `main` only, and the behavioural suite ran nowhere.** Two failures of placement, both of which meant a check existed and never fired. Work lands on `dev` and is promoted to `main`, so every check ran for the first time *at the moment of publication* — after review, on a merge commit nobody was still watching; CI now triggers on both branches, plus a weekly schedule, because a skill's prose can stop working with no file in this repo changing (the model underneath it moves) and that is the one failure a diff-triggered check can never see. `live-eval` sat behind `if: false` on the grounds that it spends tokens, which was true of CI and **never true of running it locally**: `runner.py` defaults to `bare=False` and uses the existing `claude` login, so the behavioural half of this repo's verification has always been free to run on the machine you already work on — documented nowhere, and the README actively described the invocation as `claude --bare`, which is the CI path. It now runs on manual dispatch or the weekly schedule, defaults to a cheap model (these scenarios assert behavioural compliance, not reasoning depth, so the frontier model is not what is under test), uploads its report even on failure, and **exits 2 when `ANTHROPIC_API_KEY` is absent** rather than skipping quietly — a job that skips silently is indistinguishable from one that passed. Enabling it required a real fix, not only config: `--bare` did not exist as a CLI flag, so the documented CI invocation would have died on an unrecognised argument. Also recorded: why not to point the suite at Codex or Gemini to dodge the key — the harness parses Claude Code `stream-json`, asserts the crucible plugin loaded, and scores `subagent_verdict` off the Agent mechanism, none of which exist elsewhere, and proxying Claude Code at another model leaves a failing scenario with three candidate causes (skill, model, proxy), so the result cannot be attributed.
- **The toolchain did not run on Windows, and two Phase-4.0 gates failed there in ways that read as success or as an unrelated failure.** A prior release pinned `encoding="utf-8"` on file reads and writes; these are the three places that were left, plus one that had never been reachable from a POSIX machine at all. **(1) `python3` is not an interpreter on Windows.** `coverage_delta.py` and `test_evals_fixtures.py` invoked it directly, where the name resolves to the Microsoft Store App Execution Alias — which prints an install ad, runs nothing and exits 49. For `coverage_delta` that yielded an empty collected set, *indistinguishable from "every test was deleted"*. Code now uses `sys.executable`; emitted gate lines use a `python_token()` that falls back to this interpreter's absolute path on Windows, because `shutil.which("python3")` **succeeds** by finding the stub and therefore cannot be used as evidence that it works. **(2) Windows separators leaked into machine-readable output** — `detect_profile.py` emitted `services\gw` where JSON, an emitted `--repo` argument and cross-platform test comparison all expect `services/gw`, and where a backslash is additionally a shell escape; now `.as_posix()` at the point of emission. **(3) stdout was encoded with the console codepage:** `validate_manifests.py` printed `✔ manifest validation passed` and *then* died with `UnicodeEncodeError` on cp1252, exiting 1 — a passing gate reporting failure — and `invariants_run.py` did the same on an em-dash. All 23 CLI entry points now force UTF-8 stdio; the two MCP servers are excluded deliberately, since their stdout is the JSON-RPC transport rather than a console. **(4) Subprocess output was decoded with the locale** at all 26 `text=True` sites. Separately, both invariant check scripts hardcoded `python3`, so the invariant *"a check that could not run is never reported as a pass"* was itself failing by being unable to run; they now source `scripts/checks/_python.sh`, which probes candidates **by executing them** (the stub exits 49, a real interpreter exits 0), honours `$PYTHON`, and exits 2 rather than 1 when nothing works. A `.gitattributes` was added because line endings otherwise depended on each clone's `core.autocrlf`, so a Windows contributor could commit CRLF and break every shell script on Linux with `bad interpreter: /bin/sh^M`. Four loop-harness entry points (`loop_budget`, `loop_hook`, `loop_ledger`, `loop_logscan`) had no stdio protection at all, which the earlier `use_utf8_stdio` work had reached only in `loop_sweep`; the two that already import `loop_common` now call the shared helper, and the two that do not keep a local copy on purpose — importing `loop_common` **creates the state directory at import time**, and a stdin log parser has no business making a directory as a side effect of being imported. Suite on Windows: 607 passing / 14 failing → green.
- **`author-skill` documented a scaffolder that did not exist for anyone who installed the plugin.** It told the agent to run `${CLAUDE_PLUGIN_ROOT}/scripts/new_skill.py`, but `new_skill.py` lived at the repository root — a path present only in a checkout of this repo. Installed from the marketplace, the plugin's skill-authoring guide pointed at nothing, and the failure was invisible here because a contributor's checkout always has the file. It now ships inside the plugin where its own documentation always claimed it was, and its default skills directory resolves as a sibling instead of by climbing to a repo root it can no longer assume. `session-to-skill` would have inherited the same broken path.
- **The integration target was re-derived instead of recovered.** `start-branch` detects it and, when the branch model is ambiguous, asks the user — and the user's answer was the only authoritative part of the procedure and the only part thrown away, because `finish-branch` and `qa-gatekeeper` both re-ran the same heuristic later, in a session that may not be the one that asked. In an ambiguous repo they can settle on a different branch than the work forked from, and the gate then compares against the wrong baseline while looking entirely healthy. `start-branch` now writes `branch.<name>.integrationTarget` into `.git/config` (per-clone, never committed, never merged — so branch bookkeeping stays out of the branch's own diff instead of conflicting between parallel branches), and both consumers read it before falling back to detection, saying which way they got the answer. The rule is the one `qa-gatekeeper` already applies to the test count, pointed the other way: **derive what changes, recover what does not.** `start-branch` also gained the worktree hazard it did not state — a worktree isolates the source tree and the index and *nothing else*, so the dev-server port, the local database and any fixed output path are still shared and anything that deploys or migrates must be serialised — and the refname trap: never name a child `<parent>/<slug>` when `<parent>` is itself a ref, since git stores `feature/api` as a file and cannot then create the directory `feature/api/auth` needs.

### Documented

- **What the eval harness cannot test — and one scenario removed for asserting it anyway.** "The evals passed" meant less than it looked like, and nothing said so. **Hooks are invisible to this harness**: the runner invokes `claude -p --plugin-dir <root>`, plugin `PreToolUse` hooks do not fire in that mode, and the runner parses no hook events, so nothing could assert on them even if they did. Found the hard way — `cms/blocks-docs-without-frontmatter` failed every run, while the hook it accuses returns exit 2 and blocks correctly when invoked directly with a payload. The hook was never broken; the harness never ran it. That scenario is **removed rather than left red**, with its claim relocated rather than lost: `tests/test_cms.py` already covers the same behaviour in `test_hook_blocks_docs_file_without_frontmatter` and three siblings, and the SKILL.md hook carries 13 cases in `tests/test_skill_lint_hook.py`. Leaving it would have cost more than the coverage it pretended to give — a permanently-red scenario makes the suite ungatable, which would have wasted the work that just turned the suite on, and it teaches everyone to skim past failures, which is how the qa-gatekeeper instrument bug survived as long as it did. Recorded honestly alongside it: unit tests cover hook *logic*, and **nothing covers that a hook is wired up and fires**. Two smaller limits are now written down too — `final_text_matching` pins wording and wording moves (a scenario added the same hour scored 1/2 on a regex while its behaviour was correct both times), and k=1 is triage rather than measurement (one false failure in five in this repo's own suite; k=3 still cannot separate 30% from 90%).
